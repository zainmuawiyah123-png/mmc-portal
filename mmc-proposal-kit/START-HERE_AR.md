# قبل الدخول إلى البوابة — مهم

تظهر رسالة **«تعذّر الاتصال بالخادم»** إذا تم فتح صفحة HTML مباشرة بالنقر عليها من داخل المجلد أو من ملف ZIP. البوابة ليست ملفاً ثابتاً منفصلاً؛ الواجهة تحتاج خادم Node.js وقاعدة بيانات SQLite حتى تعمل المصادقة والعطاءات والتقييم.

## الطريقة الأسهل على Windows

1. فك الضغط عن ملف المشروع بالكامل.
2. ثبّت Node.js 20 أو أحدث من الموقع الرسمي إذا لم يكن موجوداً.
3. انقر مرتين على الملف `start-local.bat` الموجود في المجلد الرئيسي.
4. انتظر حتى تظهر رسالة الخادم على المنفذ `4000`.
5. افتح المتصفح على:

   `http://localhost:4000/procurement/index.html`

لا تغلق نافذة الخادم أثناء استخدام النظام. لإيقافه اضغط `Ctrl+C` داخل النافذة.

## الطريقة على Linux أو macOS

من داخل المجلد الرئيسي للمشروع شغّل:

```bash
chmod +x start-local.sh
./start-local.sh
```

ثم افتح:

```text
http://localhost:4000/procurement/index.html
```

## حساب مستخدم المشتريات

بعد تشغيل الخادم لأول مرة، يمكن إنشاء حساب مشتريات من مجلد `server`:

```bash
node src/seed.js --email=buyer@company.com --password=Secret1234 --name="لجنة المشتريات" --role=buyer
```

بعدها ادخل من:

```text
http://localhost:4000/portal/pt-9f3c7a1e5b2d/login.html
```

## روابط النظام بعد تشغيل الخادم

- بوابة المشتريات: `/procurement/index.html`
- بوابة المقاول: `/bid/index.html`
- البوابة العامة وتسجيل الدخول: `/portal/pt-9f3c7a1e5b2d/login.html`
- دليل النظام PDF: `/documents/MMC-tender-platform-bilingual.pdf`

## لماذا لا يكفي فتح الملف مباشرة؟

عند فتح `index.html` بالنقر المباشر يصبح العنوان من نوع `file:///...`، بينما JavaScript يحاول طلب `/api/auth/me` وطلبات العطاءات من خادم HTTP. لذلك يفشل الاتصال. يجب دائماً فتح الرابط الذي يبدأ بـ `http://localhost:4000` بعد تشغيل الخادم.

## خطأ `better_sqlite3.node is not a valid Win32 application`

إذا ظهر هذا الخطأ على Windows، فمعناه أن نسخة `better-sqlite3` داخل المجلد بُنيت على نظام تشغيل آخر. احذف مجلد `server/node_modules` ثم شغّل `start-local.bat` من جديد؛ سيعيد الملف تثبيت وبناء الوحدة الأصلية بما يناسب Windows. لا تنقل مجلد `node_modules` بين Linux وWindows.

## ملاحظة النشر

في النشر الفعلي على خادم أو استضافة سحابية، يبقى Node.js قيد التشغيل خلف نطاق الموقع، ولا يحتاج المستخدم إلى تشغيل ملفات `start-local`. هذه الملفات مخصصة للتشغيل المحلي والتجربة فقط.
