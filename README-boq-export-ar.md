## ١) ما أُضيف في هذا الإصدار

| الملف | الحالة | الوصف |
|---|---|---|
| `server/src/lib/mmc-ai/xlsx-writer.js` | **جديد** | كاتب XLSX بلا أي تبعية جديدة — يبني حزمة OOXML مباشرة (ZIP + deflate من `node:zlib`) |
| `server/src/lib/mmc-ai/boq-export.js` | **جديد** | محرك التصدير: يفصل المعتمد عن غير المعتمد، ويبني أوراق العمل الخمس |
| `server/src/routes/mmc-ai-bim-model.js` | معدَّل | مسار التصدير + مسار المعاينة + حفظ سجل التصدير |
| `server/src/lib/mmc-ai/bim-model.js` | معدَّل | تتبّع مصدر كل عنصر، ونقله إلى كل بند كمية |
| `server/src/migrate.js` | معدَّل | أعمدة المصدر + جدول `ai_bim_exports` |
| `webpages/technical-proposal-kit_v5/mmc-ai/index.html` | معدَّل | زر التصدير + زر المعاينة + عمود «اللوحة المصدر» في جدول الكميات |
| `server/scripts/bim-boq-export-proof.js` | **جديد** | إثبات على مخطط حقيقي |
| `server/tests/mmc-ai-boq-export.test.js` | **جديد** | 4 اختبارات API |

**لماذا كاتب XLSX خاص بدل مكتبة؟** المشروع لا يحتوي أي مكتبة جداول، وإضافة واحدة تعني تبعية إنتاجية جديدة لتصدير واحد. الكاتب يكتب OOXML مباشرة، ويُختبر بقراءة مستقلة عبر `openpyxl`.

## ٢) ربط كل بند بلوحته المصدر — كيف يعمل

### ٢.١ سلسلة المصدر

المصدر يُسجَّل على **العنصر**، ثم ينتقل تلقائياً إلى **بند الكمية**:

```
العنصر (جدار W1)
  source: { sheetNumber:'A-101', sheetName:'Ground Floor Plan',
            pageNumber:1, documentName:'arch.pdf', revision:'C', layer:'A-WALLS' }
        ↓  measureModel()
بند الكمية (Q-WALL-NET-AREA)
  sources: [ { ...نفس المصدر, label:'A-101 — Ground Floor Plan — صفحة 1',
               elementCount:5, quantity:14.2 } ]
  sourceLabel: 'A-101 — Ground Floor Plan — صفحة 1'
        ↓  buildApprovedBoqWorkbook()
صف Excel
  اللوحة المصدر | رقم اللوحة | الصفحة | ملف المصدر
  A-101 — … — صفحة 1 | A-101 | 1 | arch.pdf
```

### ٢.٢ الحقول المقبولة في `source`

| الحقل | مثال | إلزامي |
|---|---|---|
| `sheetNumber` | `A-101` | لا |
| `sheetName` | `Ground Floor Plan` | لا |
| `pageNumber` | `1` | لا |
| `documentName` | `arch.pdf` | لا |
| `revision` | `C` | لا |
| `layer` | `A-WALLS` | لا |
| `engine` | `dxf` / `pdf-vector` / `ocr` | لا |

**كلها اختيارية، لكن ما لا يُسجَّل لا يُخترع.** بند بلا مصدر يظهر في عمود «اللوحة المصدر» بالنص **«غير مسجّل»** — لا برقم لوحة وهمي.

### ٢.٣ بند يجمع عناصر من أكثر من لوحة

إذا ساهمت عناصر من لوحتين في بند واحد (مثل «حجم الخرسانة للأعمدة» من S-201 وS-202)، يُعرض المصدران مفصولين بـ `|`، ويُحسب لكل مصدر عدد عناصره وكميته:

```
S-201 — Foundation Plan — صفحة 2 | S-202 — Slab Plan — صفحة 3
```

## ٣) قاعدة التصدير: المعتمد فقط

### ٣.١ ما يُصدَّر

| حالة الكمية | النتيجة |
|---|---|
| `approved` | ✅ يُصدَّر في ورقة «جدول الكميات المعتمد» |
| `measured_ready_for_review` | ❌ يُستبعد، ويُدرج في ورقة «غير المعتمد» مع السبب |
| `rejected` | ❌ يُستبعد، ويُدرج في ورقة «غير المعتمد» |

### ٣.٢ التكلفة

| حالة التكلفة | ما يظهر في خانات السعر |
|---|---|
| `approved` | سعر الوحدة والإجمالي بالأرقام |
| `cost_draft_requires_review` | النص **«غير معتمد»** — لا رقم |

**هذا مقصود:** كمية معتمدة بتكلفة غير معتمدة تُصدَّر بكميتها، لكن خانات السعر تقول «غير معتمد» بدل عرض رقم لم يوافق عليه أحد. ويُنبَّه إلى ذلك في رأس الورقة.

### ٣.٣ لا حذف صامت

كل بند غير معتمد يُدرج في ورقة «غير المعتمد» مع سببه. الملف لا يبدو مكتملاً وهو ناقص.

## ٥) مسارات API

### ٥.١ التصدير

```
GET /api/mmc-ai/projects/:projectId/bim/model/:modelId/boq-export.xlsx
```

يُرجع ملف `.xlsx` مباشرة. الترويسات المفيدة:

| الترويسة | المعنى |
|---|---|
| `X-Export-Approved-Rows` | عدد البنود المعتمدة المصدَّرة |
| `X-Export-Excluded-Rows` | عدد البنود المستبعدة |
| `X-Export-Sha256` | بصمة الملف — تُحفظ في السجل |

### ٥.٢ المعاينة (JSON)

```
GET /api/mmc-ai/projects/:projectId/bim/model/:modelId/boq-export/preview
```

يُرجع نفس ما سيُصدَّر، قبل التنزيل:

```json
{
  "approvedCount": 10,
  "excludedCount": 1,
  "approved": [
    { "ruleId": "Q-WALL-NET-AREA", "unit": "m2", "quantity": 14.2,
      "unitRate": 10, "total": 142, "costApproved": true,
      "provenance": { "label": "A-101 — Ground Floor Plan — صفحة 1",
                      "sheet": "A-101", "page": "1", "file": "arch.pdf" } }
  ],
  "excluded": [ { "ruleId": "Q-SLAB-AREA", "reasonAr": "الكمية لم تُعتمد بعد…" } ],
  "exports": [ { "filename": "BOQ_…xlsx", "sha256": "…", "row_count": 10 } ]
}
```

### ٥.٣ سجل التصدير

كل تصدير يُحفظ في جدول `ai_bim_exports`: من أنشأه، ومتى، وحجم الملف، وبصمته، وعدد صفوفه، ونطاقه. ويُسجَّل أيضاً في سجل التدقيق (`bim_boq_exported`).

## ٧) الإثبات على مخطط حقيقي

`node scripts/bim-boq-export-proof.js`

يقرأ مخطط DXF المعماري الموجود في المشروع، ويبني منه نموذجاً بـ27 عنصراً، ويحصر 13 بنداً، ويضع أسعار وحدة، ويعتمد، ويصدّر.

| البند | القيمة |
|---|---|
| عناصر النموذج | 27 (5 جدران · 1 فتحة · 9 أعمدة · 9 أساسات · 1 بلاطة · 2 كمرة) |
| بنود الكميات | 13 |
| المجاميع | 150 م² · 42.246 م³ · 50 م · 19 عدد |
| إجمالي التكلفة | 7,592.30 ر.ع |
| حجم الملف | 9,946 بايت |
| اللوحات في الملف | A-101 و S-201 — كلتاهما ظهرت |
| **الفحوص** | **13/13 في مصفوفة الفحوص** + تحقق مستقل بقارئ خارجي |

**التحقق المستقل:** الملف يُقرأ بـ `openpyxl` (ليست من كود المشروع) للتأكد من أنه يُفتح وأن القيم صحيحة. هذا تحقق منفصل عن الفحوص الثلاثة عشر ولا يُحسب معها.

**الفحوص التي أُجريت (13 فحصاً آلياً + تحقق خارجي):**

1. الملف حزمة ZIP صالحة
2. خمس أوراق
3. صف لكل بند معتمد
4. البند غير المعتمد **ليس** في ورقة الكميات
5. البند غير المعتمد **موجود** في ورقة «غير المعتمد»
6. كل صف يذكر رقم لوحة
7. اللوحتان A-101 وS-201 ظاهرتان
8. اسم ملف المصدر في كل صف
9. تسمية المصدر تذكر الصفحة
10. إجمالي التكلفة المصدَّر = إجمالي المحرك
11. كل كمية مصدَّرة = الكمية المحسوبة
12. كل وحدة مطابقة لوحدة القاعدة
13. كل صف يسجّل من اعتمد ومتى

وبعدها — خارج المصفوفة — يُفتح الملف بقارئ مستقل (`openpyxl`) للتأكد من أنه ليس مجرد ZIP سليم بل ملف Excel حقيقي يُقرأ.

## ٨) الاختبارات

| المجموعة | قبل | بعد |
|---|---|---|
| `npm run test:mmc-ai` | 289 (288 ناجح + 1 متجاوز) | **293** (292 ناجح + 1 متجاوز، 0 فاشل) |
| `npm test` | 91 | **91** (بلا تغيير) |

الاختبار المتجاوز واحد في كلا الإصدارين: اختبار OCR يحتاج حزم لغات Tesseract غير المتوفرة في هذه البيئة — لم يُضف في هذا الإصدار ولم يُحذف.

الاختبارات الأربعة الجديدة:

1. **التصدير الكامل** — بناء نموذج، اعتماد، أسعار، اعتماد تكلفة، تصدير، ثم قراءة البايتات والتحقق من كل عمود. وتشمل التحقق أن التكلفة **المسودة** لا تُصدَّر كسعر.
2. **الاستبعاد** — بند يُعاد إلى «بانتظار المراجعة» بعد الاعتماد: يجب ألا يظهر في الكميات، ويجب أن يظهر في ورقة الاستبعاد.
3. **بلا مصدر** — نموذج بلا مصادر: كل صف يقول «غير مسجّل»، لا رقم لوحة مخترع.
4. **الصلاحية** — غير العضو لا يستطيع التصدير (404).

## ٩) حدود ما أُنجز — بصراحة

1. **المصدر يُسجَّل عند بناء النموذج، لا يُستنتج لاحقاً.** النماذج المبنية قبل هذا الإصدار ليس فيها مصادر، وستظهر بنودها «غير مسجّل». لا يوجد ترحيل عكسي يخترع مصادر.
2. **لا تصدير PDF ولا CSV** — Excel فقط.
3. **لا تصدير متعدد النماذج في ملف واحد** — نموذج واحد لكل ملف.
4. **لا رسوم بيانية داخل Excel** — أرقام وجداول فقط.
5. **لا تنسيق شرطي** — لا تلوين تلقائي للبنود المتأخرة أو المتجاوزة.
6. **الملف لا يُوقَّع رقمياً** — البصمة (SHA-256) تُحفظ وتُعرض، لكنها ليست توقيعاً إلكترونياً.
7. **لا تصدير للبرنامج الزمني** — التصدير يغطي الكميات والتكلفة، لا الأنشطة.
8. **الأسعار من كتاب أسعار الإثبات** — ليست أسعار سوق.
9. **لم يُقس الأداء على نموذج كبير** — أكبر ما جُرّب 27 عنصراً و13 بنداً. نموذج بآلاف العناصر لم يُختبر.
10. **الواجهة بالإنجليزية** — أسماء الأزرار والأعمدة في الواجهة إنجليزية، بينما محتوى ملف Excel عربي.

**تنبيه مهني:** الملف يعكس ما اعتُمد فقط. الكميات آلية محسوبة من هندسة النموذج، ولا تصلح للتسعير أو التوريد قبل مراجعة مهندس مختص. الاعتماد في النظام يُسجَّل باسم من اعتمد ووقته، لكنه لا يُغني عن التوقيع المهني المعتمد في بلدك.

## ١٠) التشغيل

```bash
cd server
npm install
npm run migrate          # يضيف الأعمدة والجدول الجديدين بأمان
npm start                # http://localhost:3000
```

ثم: `/mmc-ai/workspace` ← اختر مشروعاً ← تبويب BIM ← افتح نموذجاً ← **Preview Export** ثم **Export Approved BOQ to Excel**.

**قبل الإنتاج:** `NODE_ENV=production` + `COOKIE_SECURE=true` + `JWT_SECRET` قوي + HTTPS + نسخ احتياطي مجدول.
