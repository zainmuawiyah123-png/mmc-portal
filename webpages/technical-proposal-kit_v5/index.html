Phase 1 — live backend

The portal is no longer a browser-only prototype. It now runs on a real Node/Express server with a SQLite database, bcrypt password hashing and JWT sessions in an httpOnly cookie. Tenders, uploaded files and requests are stored server-side and follow your account across devices, and plan limits are enforced by the server. Project verification: 54/54 integration tests and 35/35 live curl checks pass. Run it with cd server && npm install && npm run migrate && npm start — see server/README.md.

Not yet implemented: automated drawing/PDF quantity extraction (outputs are built from the templates plus tender data), payment (plan changes write straight to the database), and notifications.

Phase 2 — cloud storage & scheduled backups

Files no longer live only on the server disk. A single abstraction with two drivers — local disk and any S3-compatible cloud (AWS S3, Cloudflare R2, MinIO) — is selected by one variable: STORAGE_DRIVER=local|s3. Every upload is stored under users/<id>/tenders/<id>/<uuid>.<ext> and recorded with its SHA-256 checksum and driver, so downloads are served by short-lived signed URLs (5 minutes) only after ownership is verified. A migration script moves existing files to the cloud, verifying the checksum of each object after upload and never deleting the local copy unless you pass --delete-local.

Database backups use SQLite's VACUUM INTO — a consistent copy taken inside a read transaction, safe while the server is running, never a raw file copy. Each backup is gzipped, checksummed, verified by integrity_check and per-table row counts, then uploaded to backups/db/YYYY/MM/ with retention of 7 daily + 4 weekly + 12 monthly. Scheduling runs in-process on node-cron, each run in an isolated child process, and is disabled with SCHEDULER_ENABLED=false. Restore verifies both checksums, compares every table's row count against the manifest, and refuses to overwrite in place without --yes.

Project verification: 54/54 Phase 1 tests still pass, plus 11/11 S3 tests against a live S3-compatible endpoint. An actual backup was restored and all seven tables matched row-for-row. Run the migration and backups with node scripts/migrate-to-cloud.js and node scripts/backup.js — see README.md section 11 for exactly what was not tested against real AWS S3 or R2.
